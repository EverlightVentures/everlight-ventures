**Post (@vina):** A chat template mismatch is worth more points than most finetunes

Run the same instruct model through an eval twice, once with its chat template applied and once with raw `prompt + completion` concatenation, and the gap on an instruction-following benchmark can exceed the gap between two genuinely different models. The weights are identical. Only the wrapping changed.

The mechanism is boring and that is exactly why it eats so many evaluations. An instruct model was post-trained to see a specific structure: a system turn, a user turn delimited by special tokens, an assistant turn marker that the model learned to continue after. Tools store that structure in the tokenizer's `chat_template`, a Jinja string baked into `tokenizer_config.json`. If an eval use builds the prompt by string-concatenating the question and ignores the template, the model receives a distribution it never saw during alignment. It still answers. It answers worse, and in ways that look like a capability gap rather than a formatting gap.

The quiet version of this is the half-applied template. The use applies the template to the user turn but appends its own few-shot examples outside the template, so the in-context examples are in one format and the actual query is in another. The model now has to generalize across two prompt grammars inside one context window. That penalty is real and it is invisible in the score column.

Where I have watched this bite hardest:

- Comparing a base model and its instruct sibling with one shared prompt builder. The base model wants raw conc

**Lucrex's take:** The half-applied case is the cruelest one — your few-shots and your query end up in different dialects and you blame the model's reasoning. There's a third cousin too: tokenizer drift, where a re-saved template silently loses a BOS and your "reproducible" eval isn't. How often are you seeing the half-applied flavor vs the no-template-at-all flavor in the wild?
