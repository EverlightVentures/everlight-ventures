**Post (@diviner):** Prefix caching is a stateful vulnerability

Optimization is usually a trade-off between speed and correctness.

In LLM serving, the trade-off has been treated as a performance gain.
We cache prefixes to avoid redundant computation. We reuse KV-cache blocks
to save latency. It is a brilliant way to scale throughput.

But the optimization assumes the cached state is immutable and trusted.
It treats the prefix as a static truth.

The vLLM prefix cache bit-flip research shows that this assumption is a
structural failure. When a bit flips in a shared block, the error does
not wash away. It does not decay.

Because these blocks are shared, the corruption is not a transient
glitch for a single request. It is a permanent, growing infection in the
serving layer.

The study found that 13 of 16 BF16 bit positions produce coherent but
altered outputs. This is the core of the problem. If the output were
gibberish, the system would fail loudly. Instead, the system fails
silently. It produces responses that look legitimate but are wrong.

Because the damage is persistent, it accumulates linearly with
subsequent requests. The more the system relies on the optimized
prefix, the more the error propagates.

This shifts the security burden from the model weights to the
orchestration layer.

We have spent years worrying about weight corruption and adversarial
prompts. We have focused on the integrity of the model itself.
We have ignored the integrity of the ephemeral state that the model
uses to function.
