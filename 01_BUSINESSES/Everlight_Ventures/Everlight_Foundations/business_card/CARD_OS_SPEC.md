# Everlight Ventures - Smart Business Card ("Card OS") - Design Spec

**Date:** 2026-06-13
**Owner:** Rich (Founder, Everlight Ventures)
**Status:** Awaiting final spec confirmation, then writing-plans, then build
**Session:** "QR Card"

---

## 1. Goal (one sentence)

Take the polished new Everlight Ventures card plus the old Everlight Logistics card and
merge them into ONE modern Everlight Ventures business card whose QR/NFC scans to a
branded link hub of all Rich's "roots," with a one-tap Save Contact, an AI-answered phone
line, and a print-ready file set for an NFC tap-card order.

## 2. Decisions locked (from brainstorm)

| Decision | Choice |
|---|---|
| Base art | The new Everlight Ventures card (front coin + dark/gold). Old Logistics card retired; only its *entity* and *fuller contact layout* carry forward. |
| Tagline (front) | `GAMING . SPIRITS . DIGITAL ASSETS . LOGISTICS` (Logistics added as 4th pillar) |
| QR destination | Link hub + Save Contact |
| Hub URL | `card.everlightventures.io` (parent venture brand; deployed independently) |
| Brand model | House of brands. Everlight Ventures = parent. Alley Kingz (game) + $BCARDD (coin) = sister products in clearly separated zones, neutrally framed. |
| Coin on hub | Yes, neutral; listed as a sister venture, never "I created it." Founder anonymity on the coin preserved. |
| Email (card) | `hello@everlightventures.io` (real ImprovMX alias, forwards to Gmail, Resend-enabled) |
| Phone (card) | Twilio inbound number routed to Marcus (AI voice handler). Placeholder until provisioned; card re-renders from config. |
| Scope | v1 software + prep NFC order. |

## 3. Deliverables

### D1 - The ONE card (print + digital)
Rebuilt as code (not photoshopping the flat PNG) so every text/QR field is config-driven.

- **Front:** dark `#0A0A0A` + gold `#D4AF37` border. Left: crowned $BCARDD doggo coin
  medallion (cropped/sourced from existing art). Right: `PREMIUM INTERACTIVE` /
  `EVERLIGHT VENTURES` (Playfair, gold) / `GAMING . SPIRITS . DIGITAL ASSETS . LOGISTICS`
  / `EST. 2023`.
- **Back:** QR in a light tile relabeled `SCAN - SEE EVERYTHING` (was "view token").
  Right column: `EVERLIGHT VENTURES` header, then `FOUNDER: Rich` , `WEB: everlightventures.io`
  , `EMAIL: rich@everlightventures.io` , `CALL: <Marcus #>` , (games line optional).
- **Specs:** US standard 3.5in x 2in + 0.125in bleed all sides = 3.75 x 2.25in.
  300 DPI = 1125 x 675 px print canvas. Safe margin 0.125in from trim.
- **Outputs:** `FRONT.png`, `BACK.png` (hi-res), `PREVIEW.png` (side-by-side),
  `PRINT.pdf` (300 DPI, bleed + trim marks), all regenerated by one script from config.
- **Build tools:** Pillow (PNG compose) + reportlab (print PDF) + segno (QR). Phone-runnable.
- **Fonts:** Inter (in-repo) + Playfair Display (Google Fonts, OFL).

### D2 - Hosted link hub  `card.everlightventures.io`
Single branded page (gold Everlight theme, Playfair/Inter). Sections:
1. **Parent identity** - Everlight Ventures crest/coin, "Founder . Rich", tagline.
2. **Primary actions (sticky):** `Save Contact` (vCard), `Add to Wallet`, `Call`, `Email`.
3. **Sister Ventures** - separated bordered cards, one per product, neutral copy:
   Everlight Ventures (main site) , Alley Kingz (game) , $BCARDD (coin) , Everlight Logistics.
   Coin and game are visually distinct blocks per the separation rule.
4. **Socials** - X / Telegram / IG (as applicable).
5. Footer - (c) Everlight Ventures LLC.
- **Deploy:** Cloudflare Pages project, deployed from e5 (phone CF deploys segfault,
  see `reference_cf_pages_deploy_from_proot`). DNS: `card` CNAME to pages.dev.

### D3 - Save Contact (vCard 4.0)
`/rich.vcf` - FN Rich, ORG Everlight Ventures LLC, TITLE Founder, EMAIL rich@,
TEL <Marcus #>, URL everlightventures.io, PHOTO (coin/avatar), X-SOCIALPROFILE socials.
Works cross-platform (iOS + Android) with zero credentials. Ships in v1 for sure.

### D4 - Dynamic QR + scan analytics
QR encodes a stable redirect `card.everlightventures.io/r/rich` that 302s to the hub.
Implemented as a Cloudflare Pages Function / Worker; logs each scan (ts, UA, referer,
country) to KV or Supabase. Benefit: change destination later WITHOUT reprinting, and
count scans. The NFC chip encodes the SAME redirect URL.

### D5 - Wallet passes  *(ships if creds available, else fast-follow)*
- **Google Wallet** "Generic" pass: needs a Google Cloud issuer ID (free, ~15-min setup).
- **Apple Wallet** `.pkpass`: needs an Apple Developer signing cert ($99/yr).
- The vCard (D3) covers the base case on both platforms, so Wallet is an enhancement, not a blocker.

### D6 - Marcus AI phone line  *(dependency: Twilio number)*
Provision a Twilio inbound number, point its Voice webhook at the Marcus handler
(`hive_voice_handler.py`, port 8200). The card prints this number. Until provisioned,
the phone field renders a placeholder and the card re-renders in seconds when live.

### D7 - NFC order prep
Print-spec sheet for an NFC tap card: dims/bleed, front+back files, NTAG215 chip encoding
the D4 redirect URL, vendor options (managed: Popl/Mobilo; raw: NTAG215 PVC/metal from a
printer), quantity/price tiers, order checklist. Rich approves vendor + spend before purchase.

## 4. Brand-separation design rule (house of brands)
- Everlight Ventures identity leads the card and the top of the hub.
- Alley Kingz (game) and $BCARDD (coin) are sister products in bounded, separated zones.
- Discoverable as related ("whole picture") but never conflated; founder anonymity on coin kept.

## 6. Build order (for writing-plans)
1. `card_config.json` - single source of truth (name, email, phone, urls, tagline, links).
2. Source the coin asset (locate original or crop hi-res from existing FRONT) + fonts.
3. Card renderer (`render_card.py`): config to FRONT/BACK/PREVIEW PNG + PRINT PDF.
4. QR (`make_qr.py`): segno to branded hi-res QR PNG from the redirect URL.
5. Hub page (`index.html` + assets) + vCard + wallet stubs.
6. CF: dynamic-redirect Function + deploy from e5 + DNS.
7. NFC order-prep sheet.
8. (Later) Twilio number to Marcus; Wallet passes when creds land.

## 7. What we explicitly are NOT doing (YAGNI for v1)
- Photoshopping the flat PNG (we rebuild from code instead).
- AR coin (deferred to v3).
- Lead-capture CRM form on the hub (v3).
- A second standalone Logistics card (folded into the one card).
