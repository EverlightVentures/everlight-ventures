The 9-phase dispatch pattern (mandatory for non-trivial work)

  1. Classify -- Marcus reads the query, matches keywords against routing_rules.
  2. Identify -- pick 3+ agents across 2+ departments.
  3. Query Blinko first -- http://163.192.19.196:1111/api/v1/note/list.
  4. Dispatch in parallel -- single message, multiple Agent tool blocks. Includes Codex (clx_delegate), Gemini (gemx_delegate), Perplexity (ppx_terminal), MCP tools.
  5. Cross-check -- each agent reviews 1-2 peer outputs, flags conflicts. Never skip on multi-domain or stakes > $100.
  6. Synthesize -- one agent merges into ONE canonical deliverable, with provenance tags [AgentName].
  7. Converge / Decide -- Lucrex resolves anything still flagged. Decision logged.
  8. Publish -- via n8n_replacements.publish_gdoc(). HTML + Google Doc + Slack card.
  9. Log -- POST to Blinko upsert + Django dashboard. :8504 session history shows the same work as Claude CLI.

Skip cross-check + synthesize ONLY for trivial single-lane work (typo, rename, one-line bug). Default to the full 9 for audits, plans, architecture, anything spanning 2+ specialty lanes.
