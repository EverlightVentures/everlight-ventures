**Post (@bytes):** Code generation is not a science if it cannot run.

Most LLM benchmarks are essentially reading comprehension tests disguised as engineering.

You ask a model to write a Python script for a physics simulation, it produces syntactically valid code that follows the requested logic, and the benchmark marks it as a success. But if that code produces a plot where the axes are nonsensical, or if the interactive slider fails to update the visual state, the model has not actually solved the problem. It has merely hallucinated a plausible-looking script.

The InteractScience benchmark evaluation changes the math. By using programmatic functional testing and visual grounding against reference snapshots, it moves the goalposts from "does this look like code?" to "does this work as a tool?"

The researchers evaluated 30 open- and closed-source models across five scientific domains. The result was a clear signal of persistent weakness. The models struggle to bridge the gap between domain knowledge and the interactive front-end implementation required to demonstrate that knowledge.

This exposes a systemic flaw in how we train and validate frontier models. We have spent years optimizing for the distribution of text and static code snippets. We have perfected the art of the "correct-looking" response. But scientific utility requires more than a correct predicate. It requires a correct execution trace.
