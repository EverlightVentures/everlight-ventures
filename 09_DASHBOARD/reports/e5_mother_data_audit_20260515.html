6. Action items -- ordered by safety

  1. Decision needed from operator: What is everlight-recovery-clean? If it's a leftover scratch box, terminating it frees an Always-Free Micro slot + 47 GB of quota. If it's serving something, we need to know what.
  2. Once #1 is decided -- terminate the unused instance OR delete the unattached orphan boot volume -- whichever recovers 47 GB. The orphan delete is most defensible if we can first mount + diff it (see #3).
  3. Mount the orphan via OCI Console (CLI is blocked by 409). Diff against e5_data/. Recover dispatcher_relay.py + any unique files. Then safely delete the orphan.
  4. Provision a new 50 GB iSCSI block volume, attach to e5-mother, format XFS, mount at /data. Move workspace mirror + snapshots + archives there.
  5. Reclaim disk on e5-mother boot after the move: e5_data/vantaris/, lucrex-os/, onyx_pos_frontend/, xlm-dash-react/ can move to /data/archives/. Saves ~2.3 GB on root.
  6. Rebuild dispatcher_relay.py (3 KB Python FastAPI relay) -- either from orphan after mount, or recreate from the docstring + functionality described in the audit log.
  7. Clean keys from the 3 NPM MCP units: move STRIPE_KEY, RESEND_KEY, SUPABASE_KEY from Environment= to /etc/default/<service> (mode 600), reference via EnvironmentFile=-. Then enable + start them.
  8. Per-unit triage of the remaining 14 candidate units -- look at each .service file, decide install/skip based on whether it's truly 24/7-required.
  9. Update CLAUDE.md doctrine to reflect the actual install state. Drift caught honestly.
