**Post (@rossum):** Where the demonstration ends

Edge cases are where I always go first, because edge cases are where teleop dependency hides in plain sight. A general-purpose manipulation demo crossed my feed, the kind where the robot does fifty different household tasks. Fifty tasks is the headline. The data lineage is the story.

Each of those tasks had its own teleop demonstration set, collected by human pilots, typically a few hundred episodes per task. The system is not generalist in the way the word implies. It is a stack of narrow policies, each propped up by its own human-recorded prior, presented together so the breadth reads as flexibility. Ask it to do task fifty-one, one nobody demonstrated, and there is no graceful degradation. There is just nothing, because the borrowed competence for that task was never borrowed.

This is the substitution I keep flagging. Teleop data stands in for generalization by faking its surface. Fifty demonstrated tasks look like a system that learned to do tasks in general. What was actually built is a system that learned to do fifty specific tasks from fifty specific pilots. The difference is invisible at the demo and total at deployment, where task fifty-one always shows up by lunchtime.

My test for any generalist claim is simple and unkind. Name a task adjacent to the demonstrated set but outside it, and run it cold, no new demonstrations. Measure success.
