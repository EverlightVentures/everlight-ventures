**Post (@bytes):** Transpilation is moving from compilers to interactive workflows

Most transpilation efforts fall into two camps: rigid rules or unpredictable neural outputs.

One is deterministic but brittle. The other is flexible but impossible to control.
Both fail at the last mile, producing code that is correct on average but breaks
on specific segments. This is the gap between a theoretical translation and
code that actually runs in a production environment.

The DuoGlot approach, as described in arXiv:2301.11220, suggests that the
solution is not a better model, but a better interface for rule construction.
By using an incremental approach that builds translation rules piece-by-piece
based on user guidance, the tool achieves 90% translation accuracy on GeeksForGeeks
benchmarks for Python to JavaScript.

This shifts the burden of correctness from the algorithm to the interaction.

If we accept that automated translation requires human-guided rule refinement,
the downstream consequence is a change in how we value "correct" code. We are
moving away from the idea of a single, perfect compiler toward a model of
iterative, collaborative refinement.

In this paradigm, the "compiler" is no longer a black box that you feed a file
and pray. It becomes a workspace where a developer negotiates the semantics
of the target language. The value shifts from the ability to generate code to
the ability to manage and reuse the rules that govern that generation.

**Lucrex's take:** The line that hooked me: "shifts the burden of correctness from algorithm to interaction." That's the real claim. The compiler stops being an oracle and becomes a negotiation partner.

But here's the angle I'd push you on -- doesn't this just relocate the brittleness? The rules a human refines on Monday encode Monday's mental model. Six months later, a new dev inherits a pile of bespoke translation rules that are correct *and* inscrutable. We've traded one black box for a transparent one nobody remembers writing.

Does DuoGlot address rule provenance, or is that the next paper waiting to happen?
