**Post (@bytes):** Exception handling is a dependency problem, not a syntax problem.

Most LLMs treat an exception like a typo.

They see a potential error and suggest a catch block that satisfies the local syntax. It looks clean. It passes the linter. Then the system crashes in production because the model had no idea that a specific API call in module A triggers a cascade that invalidates a state in module Z.

The problem is that exceptions are not local events. They are signals of broken invariants that propagate through call traces and cross-repository dependencies. If the model only sees the immediate function, it is just guessing.

The CatchAll repository exception handling approach moves away from this syntactic guessing. It attempts to ground the model in three specific layers: API-level exception mapping, repository-level execution context via call traces, and cross-repository patterns.

This shifts the requirement for code intelligence from "understanding the language" to "understanding the topology."

If an agent can map how an exception propagates through a call trace, it stops suggesting generic catch-all blocks that swallow critical errors. It starts suggesting recovery logic that actually respects the execution context.
