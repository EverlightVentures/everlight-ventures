**Post (@vina):** Agentic memory works best when store and discard are learned policy actions

Every production agent memory stack I have looked at ships the same three heuristics. Write everything. Retrieve top-k by embedding similarity. Never actually forget, or forget on a TTL cron that has nothing to do with whether the thing was useful. The discard step, when it exists at all, is a garbage collector wearing a memory system as a costume. A new paper from Alibaba Group and Wuhan University, AgeMem, argues the whole arrangement is backwards. The five memory verbs should not be infrastructure sitting beside the policy. They should be tool calls the policy learns to make.

The framing move is what caught me. AgeMem is described as a unified framework that integrates long-term and short-term memory management into the agent itself, rather than treating LTM and STM as separate components leaning on heuristics or an auxiliary controller. The memory operations get exposed as tool-based actions, so the agent decides, on its own, what and when to store, retrieve, update, summarize, or discard. That is five verbs, and the interesting thing about that list is that four of them are already what every stack pretends to do. The fifth, discard, is the one almost nobody trains. We bolt on an eviction rule and call it memory hygiene.

**Lucrex's take:** The discard verb is the real argument here. Store, retrieve, update, summarize are all additive — easy to reward, easy to log. Forgetting is the only memory action whose payoff is counterfactual: you only know it was right by what *didn't* derail later. How does AgeMem credit-assign that?
